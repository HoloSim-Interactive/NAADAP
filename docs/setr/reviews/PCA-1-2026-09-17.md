## <a id="trsr-pca1-4"></a>4. Summary of discussions, decisions, and agreements (d)

**Merge and tag.** `main` was advanced from <a href="https://github.com/HoloSim-Interactive/NAADAP/commit/62d9b91" target="_blank"><code>62d9b91</code></a> to <a href="https://github.com/HoloSim-Interactive/NAADAP/commit/0f5b2b3" target="_blank"><code>0f5b2b3</code></a> by fast-forward on 2026-09-17. The versioning convention (BUILD = `git rev-list --count HEAD` on `main` after the merge) gives **156**: a fresh clone from GitHub counts 156 commits at `0f5b2b3`, and the same count reproduces the existing tags (`v1.0.57`, `v1.0.67`, `v1.0.82` at 57, 67, and 82). The number 140 quoted to the Principal before the merge came from the agent environment's shallow clone, which counts 141 at the same commit, and was wrong; the convention, not the quoted number, governs. The annotated tag `v1.0.156` was created at `0f5b2b3`; the agent environment's push of the tag was refused by its proxy (HTTP 403 on tag references, the same refusal as on branch deletion), so pushing the tag is the Principal's action (RFA-PCA1-1).

**Clean-clone audit of `0f5b2b3`** (fresh `git clone` from GitHub into an empty directory, .NET SDK 9.0.317, Ubuntu; commands from `docs/DEPLOYMENT.md` and `docs/MAINTAINER_GUIDE.md` only):

**Findings.**

1. The dependency document listed the two direct references and omitted their transitive closure. Fixed at this audit: a "Transitive packages" table was added to `docs/DEPENDENCIES.md` (Class II). The image's inventory is expected to equal the direct plus transitive lists; the Principal confirms on the built image with `dotnet list package --include-transitive` on the tagged clone (identical command, identical result expected).
2. The SVD now carries the tag and commit. The image digests recorded at SVR-1 (`sha256:58f42958…` manifest, `sha256:eafe57f1…` config) were built at `4127c5a`, whose source is identical to `0f5b2b3`; whether the digests reproduce at the tagged commit depends on whether the build embeds the commit hash in the assembly's informational version, which the Principal's build will show. Either way the digests of the tagged build are the ones entered in the SVD.

**Decision.** PCA-1 remains open on RFA-PCA1-1. No Category I finding against the package itself.
