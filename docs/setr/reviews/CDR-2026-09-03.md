## 6. Decisions recorded at this review

| Decision | Basis |
| --- | --- |
| Single linear build order, Core Clustering as early as its real prerequisites allow | Solutions Architect's feasibility read (Core is the highest technical risk) and the Product Manager's value read (non-LLM core and its outputs before the optional LLM step) agreed once laid out |
| Classic `.sln` format forced with `-f sln` | `dotnet new sln` on SDK 9.0.3xx defaults to `.slnx`; the classic format is what Visual Studio opens without question (DELIV-910) |
| xunit as the test framework | "A standard .NET test framework"; justification recorded in each test `.csproj` per DELIV-920 |
| Windows verification workflow to be copied by a human once, before consolidation | No agent identity can write to `.github/workflows/`. Done by the Principal 2026-09-14. |
| No RTVM item marked Verified by the scaffold alone | CORE-240, DELIV-910, DELIV-920, NFR-500 each verified later in their own issues, so the scaffold's structural compliance did not pre-empt functional verification |
